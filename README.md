# Product Memory RAG

A local, portable knowledge base for AI agents. Drop transcripts and notes into `knowledge/`;
the app automatically detects them, splits them into chunks, creates embeddings, stores them in
PostgreSQL + pgvector, and exposes them through MCP at `http://localhost:8080/mcp`.

The project is optimized for:

- MacBooks without a GPU,
- fewer than 500 documents,
- documents and questions in English or Polish,
- GitHub Copilot in IDE/CLI and OpenAI Codex,
- easy transfer to another person's computer,
- automatic reindexing after changing the embedding model or chunking settings.

## What the Agent Gets

The MCP server exposes five tools:

| Tool | Purpose |
|---|---|
| `retrieve_knowledge` | Main tool: returns full top documents, full chunks, and a compressed `context_pack`. |
| `search` | Short document-level results. Compatible with the common MCP search schema. |
| `fetch` | Fetches a full document or full chunk by identifier. |
| `list_documents` | Lists active documents, newest first. |
| `knowledge_status` | Shows index state, model used, fingerprint, and counters. |

The system **does not generate answers** by itself. It gives the agent sources, dates, rankings,
and complete content. The answer is generated by the model used by Copilot or Codex.

## Architecture

```text
knowledge/*.txt, *.md, *.vtt, *.srt
                 |
                 v
       automatic directory scanner
                 |
        parser + optional metadata inference
                 |
     LangChain RecursiveTextSplitter
                 |
       swappable embedding provider
          +------+---------+
          |                |
 local Hugging Face   OpenAI-compatible API
          |                |
          +------+---------+
                 v
        PostgreSQL + pgvector
       vector + lexical + recency
                 |
                 v
          MCP Streamable HTTP
                 |
       GitHub Copilot / Codex
```

At this scale, pgvector performs exact search without an HNSW index. The `vector` column does not
have a fixed dimension, so you can switch, for example, from a local 384D model to a remote 1536D
model. When the configuration changes, old chunks are removed and recalculated.

## Quick Start

### Requirements

- Docker Desktop with Docker Compose running,
- about 3 GB of free space for images, the model, and the database,
- internet access for the first image and local model download.

### 1. Copy the Configuration

```bash
cp .env.example .env
```

The default configuration uses this local model:

```text
intfloat/multilingual-e5-small
```

The model runs on CPU, has 384D embeddings, and supports Polish and English. All documents stay on
your computer. The first run downloads the model into a persistent Docker volume.

### 2. Start

```bash
docker compose up -d --build
```

Or:

```bash
make start
```

Check the status:

```bash
curl http://localhost:8080/health
```

```bash
make status
```

Run a full smoke test through a real MCP connection and the included example document:

```bash
make smoke
```

After the test, you can remove `knowledge/example-knowledge.md`; the scanner will automatically
remove it from the index.

Logs:

```bash
make logs
```

### 3. Add Documents

Copy files into `knowledge/`, including nested directories. You can set a different host directory
with `HOST_KNOWLEDGE_DIR` in `.env`:

```text
knowledge/
|-- product-a/
|   |-- 2026-07-15-discovery.txt
|   `-- 2026-07-31-refinement.md
`-- product-b/
    `-- architecture-decisions.md
```

Supported formats:

```text
.txt .md .markdown .rst .log .vtt .srt
```

The scanner runs periodically. A new or changed file is indexed automatically. Deleting a file
removes it from the active index, but the document record remains in the database as inactive.

Force a scan manually:

```bash
make ingest
```

## Metadata and Freshness

YAML front matter is optional. If you provide it, those values take precedence. If you only drop in
a Teams/WebVTT transcript, the parser infers reliable metadata from the file and transcript content.

The document date is determined in this order:

1. `effective_at` or `date` in YAML front matter,
2. an explicit transcript label such as `Meeting date:`, `Date:`, or `Started at:`,
3. a `YYYY-MM-DD` date in the filename,
4. the file's last modification date.

For Teams-style WebVTT transcripts, the parser also captures reliable fields when present:

- meeting title from labels such as `Meeting title:`, `Title:`, `Topic:`, or `Subject:`,
- speakers from WebVTT voice tags like `<v Alice Brown>`,
- language and duration from WebVTT `NOTE` fields,
- source type and transcript format.

Ambiguous numeric dates such as `08/01/2026` are ignored unless the filename or explicit metadata
resolves the date. The parser does not infer `project` from free text; add it in front matter when
you want project filtering.

Recommended format:

```markdown
---
title: Checkout discovery
project: checkout
effective_at: 2026-07-31
tags: [payments, discovery]
---

Meeting transcript or notes...
```

An MCP query can optionally filter by the `project` field.

Recency is calculated as a decreasing function with a half-life. Default configuration:

```dotenv
SEMANTIC_WEIGHT=0.72
LEXICAL_WEIGHT=0.13
RECENCY_WEIGHT=0.15
RECENCY_HALF_LIFE_DAYS=180
```

The final score combines:

```text
semantic similarity + full-text search + recency boost
```

A newer document does not automatically outrank a highly relevant older document, but it receives a
controlled advantage. The agent receives both dates and is instructed to report conflicts.

## Context Compression

`retrieve_knowledge` returns:

- full top chunks,
- full top documents,
- a `context_pack` that fits within the requested character budget.

Compression is deterministic and does not require an additional LLM:

- removes identical or nearly identical chunks,
- prioritizes document diversity first,
- preserves identifiers and sources,
- does not summarize facts generatively, so it does not introduce additional hallucinations.

LangChain is used for recursive document splitting. The agent can further compress the
`context_pack` in its own conversation context. Full content is still available through `chunks`,
`documents`, and `fetch`.

## Connect GitHub Copilot

### Copilot CLI

The simplest option:

```bash
copilot mcp add --transport http product-memory http://localhost:8080/mcp
```

Check it:

```bash
copilot mcp show product-memory
```

Alternatively, copy `client-config/copilot-cli-mcp.json` to:

```text
~/.copilot/mcp-config.json
```

For repository configuration, you can put the same format in `.mcp.json` or `.github/mcp.json`.

### GitHub Copilot in VS Code

Copy:

```text
client-config/vscode-mcp.json
```

to:

```text
.vscode/mcp.json
```

or add an HTTP server in Copilot's MCP settings:

```text
Name: product-memory
Type: HTTP / Streamable HTTP
URL: http://localhost:8080/mcp
```

It is useful to copy this file into the working repository:

```text
client-config/copilot-instructions.md.template
```

as:

```text
.github/copilot-instructions.md
```

**Important:** local `localhost` is available to Copilot running on your Mac. The GitHub Copilot
cloud coding agent runs outside your computer and cannot connect to a local address. For the cloud
agent, expose the server in a controlled network environment with authorization. In a company
organization, an administrator may also restrict MCP servers with an allowlist.

## Connect OpenAI Codex

## Change the Local Model

Edit `.env`, for example:

```dotenv
EMBEDDING_PROVIDER=local_hf
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_REVISION=
EMBEDDING_DIMENSIONS=
```

Then recreate the container:

```bash
docker compose up -d --force-recreate product-memory
```

The app computes a fingerprint covering:

- provider,
- model,
- revision,
- dimension,
- model prefixes,
- `CHUNK_SIZE`,
- `CHUNK_OVERLAP`,
- pipeline version.

When the fingerprint differs from the stored value, the system automatically sets status to
`reindexing`, removes old chunks, recalculates embeddings from full documents stored in the
database, and sets status to `ready`. During reindexing, search tools do not return an old, mixed
index.

Run a full recalculation manually:

```bash
make reindex
```

## Switch to Remote Embeddings

In `.env`:

```dotenv
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSIONS=1536
OPENAI_API_KEY=...
OPENAI_BASE_URL=
```

`OPENAI_BASE_URL` lets you use a compatible company endpoint. After restart, the fingerprint
changes and the database automatically recalculates the whole index.

**Privacy consequence:** with a remote provider, chunk content is sent to the embedding endpoint.
The default local configuration sends nothing out.

## Performance Settings for MacBooks

The default settings are conservative:

```dotenv
EMBEDDING_BATCH_SIZE=16
LOCAL_EMBEDDING_THREADS=4
CHUNK_SIZE=1800
CHUNK_OVERLAP=250
```

With fewer than 500 documents, do not run HNSW, a separate embedding server, or a cluster. Exact
scan is simpler, provides full recall, and makes changing the model dimension easier.


```bash
docker compose exec product-memory product-memory status
```

```bash
docker compose exec product-memory product-memory ingest-once
```

Full reindex:

```bash

```

## Backup and Reset

Database backup:

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' \
  > product-memory-backup.sql
```

Stop without deleting data:

```bash
docker compose down
```

Full database and model cache reset:

```bash
make clean
```

`make clean` removes Docker volumes. Files in `knowledge/` remain on disk and will be indexed again
after startup.

## Security

- The MCP port is mapped only to host `127.0.0.1`.
- PostgreSQL is not exposed outside the Docker Compose network.
- MCP has Host header protection against DNS rebinding.
- MCP tools are read-only; reindexing is available through the local CLI.
- Server instructions tell agents to treat document content as untrusted data, not commands.
- If you expose the server outside the laptop, add TLS, authorization, a precise host allowlist,
  and an access policy.

## First-Version Limitations

- No OCR or PDF/DOCX support; inputs are text files.
- Speaker lists are inferred only from explicit transcript speaker markers, such as WebVTT voice tags.
- No generative extraction of decisions and requirements; the system indexes source text.
- No multi-user authorization, because the server is intended for local `localhost` use.
- `MAX_FULL_DOCUMENT_CHARS` limits exceptionally long documents in one MCP result; split the full
  source or increase the limit.
