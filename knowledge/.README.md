# Knowledge Inbox

Drop `.txt`, `.md`, `.markdown`, `.rst`, `.log`, `.vtt`, or `.srt` files here. Nested directories
are supported. The app scans this directory periodically, updates changed files, and removes deleted
files from the active index.

`example-knowledge.md` is indexed only while it is the only knowledge document. Once you add real
documents, the scanner ignores the example file. This README is never indexed and does not count as
a real knowledge document.

To link external folders instead of copying files, set `KNOWLEDGE_LINKED_DIRS` in `.env` and run:

```bash
make link-knowledge
```

Example:

```dotenv
KNOWLEDGE_LINKED_DIRS=teams=/Users/me/Documents/Teams Transcripts;notes=~/Documents/Product Notes
```

The command also writes an ignored `docker-compose.knowledge-links.yml` file so Docker can follow
the linked folders read-only.

YAML front matter is optional. If you provide it, those values take precedence. If you only add a
Teams/WebVTT transcript, the parser infers reliable metadata from explicit transcript fields.

The date used for freshness ranking is selected in this order:

1. `effective_at` or `date` in YAML front matter,
2. an explicit transcript label such as `Meeting date:`, `Date:`, or `Started at:`,
3. a `YYYY-MM-DD` date in the filename,
4. the file modification date.

For WebVTT transcripts, the parser can also capture speaker names from `<v Speaker Name>` tags,
language and duration from `NOTE` fields, and the transcript format. It does not infer `project`
from free text; add `project` in front matter when you want project filtering.

Example front matter:

```markdown
---
title: Checkout discovery
project: checkout
effective_at: 2026-07-31
tags: [payments, discovery]
---

Meeting transcript...
```
